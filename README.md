# Camofox official release mirror

Personal maintenance pipeline for [jo-inc/camofox-browser](https://github.com/jo-inc/camofox-browser). Not an upstream project. No source rebuilds or NAS deployment.

Manually dispatch **Verify and mirror official Camofox**. Default is test-only, without Docker Hub credentials. Publication requests from non-main refs are rejected; scheduled/main publication alone receives the `DOCKERHUB_TOKEN` Actions secret for Docker Hub account `flying864`. Configure it in GitHub Settings > Secrets and variables > Actions. Never commit credentials. Publication authentication uses a private temporary directory removed on success, login failure or copy failure (ephemeral runner teardown remains the backstop for forced termination). All safety gates use explicit exceptions, remain active under Python `-O`, and tests run in both modes. Cleanup failure blocks publication but does not obscure an earlier probe error. No-change runs keep stdout silent while writing an explicit `unchanged` Actions summary.

The pipeline selects the greatest stable `vX.Y.Z` release (excluding backup releases), resolves its official GHCR `linux/amd64` manifest, captures the previous Docker Hub digest for rollback, pulls by digest, and verifies image config/architecture. A temporary loopback-only container with 2 GB shared memory must pass health, version and three independent controlled HTTP navigation/content/cleanup checks. The fixture server binds only to loopback inside the disposable container, with a unique per-session URL and content nonce plus heading/link checks; it is not added to the mirrored image. This avoids depending on mutable third-party example.com content. This smoke test does not certify public Internet DNS/TLS or NAS proxy connectivity. Only then may it push `flying864/camofox-browser:latest`. Publication uses digest-preserving registry copy and is confirmed by exact platform manifest, config and ordered layer digest equality.

A failed test blocks publishing. There is no source-build fallback. The sole waiting outcome is when the selected release's version-tag manifest request returns HTTP 404 with a valid registry JSON body whose non-empty `errors` list contains only `MANIFEST_UNKNOWN`: the run exits successfully with an explicit notice that no tests or publication occurred, before any downstream-registry or Docker access. Authentication/token errors, 401/403, 429, 5xx, malformed or plain-text 404 responses, mixed/empty registry errors, missing `linux/amd64`, child-manifest failures, smoke-test failures and publication failures remain hard failures; waiting is never reported as a successful mirror. Previous digest is in the run log; rollback requires an explicit decision. Runs daily at 10:00 Asia/Shanghai (02:00 UTC), with publishing enabled for scheduled events. If the official amd64 manifest and Docker Hub identity already match, it exits silently without pulling, testing or pushing. Repository Actions retention is set to 7 days for new logs/artifacts; this does not retroactively shorten existing logs, and no historical runs are manually deleted. No image artifacts, persistent caches, keepalive activity, paid larger runners, production proxy settings or LAN connections are configured. GitHub-hosted standard Ubuntu is used with a 25-minute deadline and serialized runs.

GitHub schedules can be delayed or dropped under load; public-repository schedules may be disabled after 60 days without repository activity. Failed runs are visible in Actions; enable GitHub Actions failure notifications in account notification settings. No Telegram alert integration is configured.

Cloud tests do not validate a NAS proxy path. Validate separately after any explicitly authorized NAS deployment.
